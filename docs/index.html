按 F8，唤醒你的音乐 App
而不是 Apple Music

AntiMusic 是一个 macOS 菜单栏工具：媒体键按下时，自动启动你指定的音乐 App（默认 QQ 音乐）并替你按下第一次播放；出声之后，媒体键交还系统正常路由。

它解决什么问题

macOS 上按媒体键永远只会唤起 Apple Music——即使你从来不用它。

🎵

冷启动一键出声

音乐 App 没开时按 F8：自动启动 → 注入播放指令 → 等待真实出声。实测冷启动到出声 1.9–2.3 秒（验收标准 ≤3s）。

🚫

Apple Music 不再弹出

CGEventTap 在事件层拦截：目标 App 在出声就放行，没出声就吞掉并触发唤醒——Apple Music 因此不会被 rcd 拉起。

🤝

出声后自动交棒

一旦检测到目标进程真实出声，媒体键全部交棒给它：暂停、恢复、F7/F9 调音量，与原生体验一致。

🧩

不止 QQ 音乐

设置里可任选音乐播放器（自动读取 Bundle ID）。注入链按优先级自动降级，每一级都可在「高级」页开关。

🔊

以「真实出声」为准

成功判据是 CoreAudio 检测到目标进程真的在输出音频，而不是"事件发出去了"。失败自动重试并逐级降级。

🧪

闭环测试架构

tests/run_all.sh 一键：构建 → 35 项状态机单元测试 → POC 套件 → 验收 → 报告。全部结论可复跑。

三步开始

首次使用需要授两处权限、配一次快捷键，之后就不用再管了。

下载并打开

下载 zip、解压，把 AntiMusic.app 拖进「应用程序」。首次打开请右键 → 打开（未公证构建，直接双击会被 Gatekeeper 拦截）。

授予两处权限

按启动弹窗引导，在「系统设置 → 隐私与安全性」里打开输入监控与辅助功能（授给 AntiMusic）。

配置 QQ 音乐全局快捷键

QQ 音乐 → 设置 → 快捷键 → 勾选「启用全局快捷键」，给「播放/暂停」绑定 ⌘⌥P；然后在 AntiMusic「设置 → 通用」里录成同样的组合键。

最容易漏的第三处权限：QQ 音乐本体也要有「输入监控」授权，否则它的全局快捷键收不到事件——典型表现是「QQ 音乐启动了但就是不放歌」。自查方法：QQ 音乐在任何前后台状态下按绑定组合键都能控制播放 ⇒ 授权正常。

按优先级自动降级的注入链

每种手段都经实弹验证，结论如实标注；全部可在设置「高级」页开关。

优先级手段实测结论（macOS 27 + QQ音乐 11.10.0）
P1 ★模拟 QQ 音乐全局快捷键广播变体首试命中（App 内 84ms 响应），主推路径
P0定向系统媒体键实测无效，留作其他版本兼容
P2URL scheme有效（1.2s 内触发播放），作为快速兜底
P3AX 点击播放菜单有效（瞬时、可靠），最后一级

常见问题

启动了但不出声？

九成是 QQ 音乐本体缺「输入监控」授权；其次是全局快捷键没绑定、或与 AntiMusic 设置不一致。日志在 ~/Library/Logs/AntiMusic/wake.log。

按 F8 毫无反应？

确认 AntiMusic 在运行（菜单栏音符图标）。建议在「系统设置 → 通用 → 登录项」里开启自启。

播放中按 F8 想暂停？

出声后媒体键由目标 App 接管，直接按即可。已知限制：合成测试事件无法覆盖该场景，须用实体按键验证。
